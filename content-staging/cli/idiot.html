IDIOT method

Intent Driven Iterative Observational Development — the acronym is the joke; the loop is the method.

INTENT → smallest change → RUN/OBSERVE → learn → repeat

Pair with Ponytail for how little code each pass needs. IDIOT picks the target; Ponytail loads the arrow. da-cli is the instrument that makes observation executable.

Open source: github.com/somarc/idiot

The five letters

Intent

State what you should see or feel — in falsifiable terms. “Footer confusing” becomes “user can name what × does while watching 1h/day spin.”

Driven

Every line in the pass serves that intent. No drive-by refactors. Scope follows observation, not architecture tours.

Iterative

One slice per pass: one gate, one chip, one footer group, one API field. Commit when the observation target moves.

Observational

Run the app, API, or preview URL yourself. Green builds and diff review are supporting evidence — not substitutes for watching delivery.

Development

Ship real changes, then observe, then report. IDIOT is not planning-only mode.

da-cli as observation runtime

On VIP migrations, the highest-value observations are delivery truths:

  • source vs .plain.html (stale preview)
  • preview vs live freshness lag
  • route ownership before delete
  • silent fallbacks on dated authoritative rows
da --format json status
da site doctor --agent --format json
da preview explain /index --format json
da site freshness / --format json

JSON envelopes return ok, warnings, and next[] — an agent handoff that encodes operator judgment.

Example pass (this site)

Intent: Document operator gates and IDIOT on da-deep without breaking CLI index navigation.

Observe: CLI reference covers subcommands; episodes are implicit. Net-new docs should match existing /cli/* voice.

Ship: Add /cli/operator-gates and /cli/idiot; link from CLI index; dry-run put → commit → preview explain.

da content put /cli/idiot.html idiot.html
da --commit content put /cli/idiot.html idiot.html
da --commit preview page /cli/idiot
da preview explain /cli/idiot --format json

Anti-patterns (actual idiot moves)

  • Spec-first implementation with no preview until the end
  • Trusting aem up when the question is about aem.page
  • Big-bang rewrites when one labeled group answers intent
  • Three paragraphs where one preview explain would settle it
