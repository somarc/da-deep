Operator gates

Mutable checkpoints between inspect and mutate. da-cli is not a thin wrapper around admin APIs — it is a gated operator runtime: dry-run first, explicit --commit to cross the line, proof commands before promotion.

This page documents the episodes practitioners actually run — not every subcommand alphabetically.

The four episodes

EpisodeQuestionRepresentative commands
Orient Where am I? What is safe to touch? da --format json status, da resolve <url>, da route classify /path, da site doctor --agent
Change What is the smallest write that serves intent? da content put (dry-run), da content clone/status/diff/commit/push, da code sync
Prove Did delivery actually change? da preview explain /path, da audit full /path, da site freshness /
Reconcile Does preview match source? Is live still honest? da site reconcile, da publish unpublish, pipeline requires_approval gates

Agents and humans share the same episodes. Agents consume JSON envelopes with next[]; humans read the same commands in the terminal.

Gate stack (default behavior)

inspect  →  dry-run  →  human/agent OK  →  --commit  →  prove  →  (maybe) publish

Write operations (content put, preview page, publish page, route clean) default to dry-run. Root --commit is the mutable gate — not a nuisance flag, the contract.

# See the diff — nothing mutates
da content put /cli/operator-gates.html operator-gates.html

# Cross the gate
da --commit content put /cli/operator-gates.html operator-gates.html

# Prove delivery moved (preview bus, not source echo)
da --commit preview page /cli/operator-gates
da preview explain /cli/operator-gates --format json

Pipeline gates

YAML pipelines compose primitives; requires_approval: true inserts a human checkpoint before irreversible steps (typical boundary: preview complete → approve → publish).

da pipeline scaffold agent-validate
da pipeline run validate.yaml          # write steps dry-run
da --commit pipeline run validate.yaml # write steps execute

See da pipeline for DAG format, parallel steps, and run-state persistence.

Field signal: stale preview

Source can be correct while .plain.html is empty — classic failure mode on VIP migrations. Local aem up fixtures can mask a frozen preview bus.

da content get /nav.html          # SOURCE — often correct
curl …/nav.plain.html             # PREVIEW — may be empty
da --commit preview page /nav     # fix is re-preview, not re-authoring

preview explain is the proof primitive: it compares authored shape against what Helix extracted.

Chameleon contract (Helix-6 and beyond)

Transport APIs may change; operator semantics should not. Stable surfaces:

  • target resolution (resolve)
  • ownership (route classify)
  • proof (preview explain, audit, freshness)
  • gates (dry-run, --commit, pipeline approval)

Adapters swap underneath. Episodes stay the same.
